# FuelWatch

Старый Android-телефон смотрит на АЗС и сообщает, когда приезжает и уезжает бензовоз.
Уведомления, кадры, зоны, состояние телефонов и все настройки — в веб-панели; Telegram — дополнительный канал.

- **Телефон** снимает сцену, сам сравнивает кадры и отправляет только те, где в зоне что-то изменилось,
  плюс плановый кадр раз в несколько минут. Следит за питанием, перегревом, сдвигом и сетью; без связи копит
  кадры и события на диске.
- **Сервер** отправляет кадры в мультимодальную модель (VLM через [OpenRouter](https://openrouter.ai)), по
  ответам ведёт визиты «приехал → стоит → уехал» и следит за здоровьем телефонов.
- **Панель** — живые уведомления, последний кадр и живой режим, редактор зон, галерея кадров с ответами модели,
  визиты с оценкой 👍/👎, графики заряда и температуры, расходы на модель, пользователи.

Людей, лица и номера система не распознаёт и не описывает, видео не пишет.

```text
android/   приложение (Kotlin, CameraX), Android 10+ (minSdk 29), без Google Play Services
server/    сервер (Go, Postgres): API телефона и панели, SSE, VLM, визиты, здоровье, Telegram
panel/     панель (React, Vite, TypeScript, Tailwind); собирается внутрь серверного бинарника
deploy/    Dockerfile, docker-compose (fuelwatch + postgres + nginx + certbot), бэкап
```

## Как это работает

1. В панели «Добавить устройство» выдаёт **одноразовый код привязки** (живёт 1 час).
2. На телефоне в FuelWatch вводится адрес сервера и код → телефон получает свой токен.
3. Телефон раз в ~20 с шлёт heartbeat (заряд, температура, очередь, наклон) и получает команды и настройки.
4. Кадры с изменениями в зоне уходят на сервер; сервер спрашивает модель «есть ли в зоне бензовоз» и после двух
   уверенных ответов шлёт «приехал», после нескольких отрицательных — «уехал».

Настройки (интервалы, пороги, модель, уведомления) меняются в панели и доходят до телефона без обновления APK.

## Установка

Понадобится сервер с Docker и доменом (A-запись на сервер) и Android-телефон 10+ с постоянным питанием.

### 1. Сервер

```bash
git clone https://github.com/famfamfam/fuelwatch.git && cd fuelwatch/deploy
cp .env.example .env    # DOMAIN, PUBLIC_URL, POSTGRES_PASSWORD, ADMIN_LOGIN/ADMIN_PASSWORD, VLM_API_KEY, VLM_MODEL
```

Сертификат, запуск, обновление и бэкап — в [deploy/README.md](deploy/README.md). Панель: `https://<домен>`.

### 2. Телефон

Сборка release APK (подписанного своим ключом) описана ниже в «Разработке». Установка — по USB:

```bash
adb install -r app-release.apk
```

На телефоне:
1. FuelWatch → адрес сервера (`https://<домен>`) и код из панели → «Привязать».
2. «Разрешить камеру и уведомления», «Работа без ограничений батареи», «Сделать FuelWatch домашним экраном» →
   «Готово». На Xiaomi, Huawei и т. п. дополнительно разрешите автозапуск в настройках приложения.

Домашний экран нужен, чтобы после перезагрузки телефон сам вернулся к работе. Экран остаётся чёрным с тусклой
строкой статуса; долгое нажатие на неё открывает настройки.

### 3. Настройка в панели

1. Вкладка «Камера» → «Живой режим»: поставить телефон, подобрать zoom.
2. «Сделать эталон» — кадр пустой сцены при дневном свете.
3. «Зоны»: нарисовать **MONITOR** там, где встаёт бензовоз, и **IGNORE** на дорогу, деревья, экраны.
4. «Включить» (режим мониторинга).
5. По желанию — Telegram: «Настройки» → «Уведомления».

## Безопасность

- Без кода привязки из панели телефон подключиться не может. Код одноразовый, живёт час, хранится хешем;
  больше 10 попыток в минуту с адреса отклоняются. Токен устройства (256 бит) хранится хешем и отзывается
  отключением или удалением устройства.
- Вход в панель — логин и пароль, cookie-сессия (HttpOnly, Secure при HTTPS), защита от CSRF и перебора.
  Первый пользователь создаётся из `ADMIN_LOGIN`/`ADMIN_PASSWORD`; пароль из `.env.example` не принимается.
- Ключ модели и токен Telegram — только в `.env` сервера. На телефоне — только токен устройства.
- Release-сборка приложения работает только по HTTPS.

## Разработка

Нужны Go 1.26, Node 24, Docker; для телефона — JDK 17+ и Android SDK (удобно через Android Studio).

```bash
# База
docker run -d --name fw-pg -e POSTGRES_USER=fw -e POSTGRES_PASSWORD=fw -e POSTGRES_DB=fuelwatch -p 55432:5432 postgres:16-alpine

# Сервер: миграции применяются при старте, первый админ — из ADMIN_*
cd server
DATABASE_URL="postgres://fw:fw@localhost:55432/fuelwatch?sslmode=disable" \
ADMIN_LOGIN=admin ADMIN_PASSWORD=dev-password go run ./cmd/fuelwatch       # :8080

# Панель с горячей перезагрузкой (проксирует /api на :8080)
cd panel && npm ci && npm run dev                                          # http://localhost:5173
```

`npm run build` в `panel/` кладёт сборку в `server/internal/panelapi/dist`; после этого `go build` отдаёт
панель сам, на том же порту. Без модели можно работать с `vision.provider = fake` в настройках панели
(всегда отвечает «бензовоза нет»).

Приложение для отладки (разрешает `http://`, сервер в локальной сети — `http://<IP компьютера>:8080`;
по USB удобно `adb reverse tcp:8080 tcp:8080` и адрес `http://localhost:8080`):

```bash
cd android && ./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Тесты:

```bash
cd server  && go test ./...
cd panel   && npm test
cd android && ./gradlew testDebugUnitTest
```

Сравнить модели или версии промпта на уже сохранённых кадрах, без влияния на визиты:

```bash
fuelwatch replay --device cam-01 --from 2026-10-01 --to 2026-10-03 --model <id модели> --out replay.csv
```

### Release APK

```bash
# один раз: ключ подписи. Храните его вне репозитория: без него обновления встанут только через удаление приложения
keytool -genkeypair -keystore ~/fuelwatch.jks -alias fuelwatch -keyalg RSA -keysize 2048 -validity 10000
```

`android/keystore.properties` (в `.gitignore`):

```properties
storeFile=/home/me/fuelwatch.jks
storePassword=…
keyAlias=fuelwatch
keyPassword=…
```

```bash
cd android && ./gradlew assembleRelease     # app/build/outputs/apk/release/app-release.apk
```

Перед каждым обновлением увеличьте `versionCode` в `android/app/build.gradle.kts`. Переход с отладочной сборки
на release — только через удаление приложения (`adb uninstall app.fuelwatch`) и новую привязку по коду.

## Ограничения

- Обновление приложения — только по USB (`adb install -r`), удалённого обновления нет.
- Качество распознавания зависит от модели и ракурса: перед работой прогоните `fuelwatch replay` на своих кадрах.
- Один модуль камеры (задняя), кадры раз в несколько секунд — это не видеонаблюдение.
